# Component Scaffold

Every component in `ui/components/` follows a fixed structure. This doc is the canonical
reference for what belongs where and when each piece is required.

## Always present

These files are generated by `pnpm gen` and must exist in every component folder.

| File | Purpose |
|---|---|
| `index.tsx` | Component function. Named export, PascalCase. Root element has `className={style.base}` and `data-testid`. |
| `style.module.css` | CSS Module. Root class is always `.base`. |
| `component.ftl` | All user-visible strings. See [FTL scope](#ftl-scope) below. |
| `component.test.tsx` | Smoke test. At minimum: renders and `data-testid` is in the document. |
| `component.story.tsx` | Storybook. One `Overview` story with controls. Title: `"ComponentName / Overview"`. |

## Conditional — inside the component folder

| File | When |
|---|---|
| `types.ts` | The component exports types consumed by other components or packages. |
| `hooks/<name>.ts` | Complex display derivation — memoized selectors, derived presentation state. |

## Conditional — separate packages

State and mocks live outside `ui/components/`. They are separate packages with their own
import aliases.

| Location | When |
|---|---|
| `data/state/<name>/index.ts` (`@data/state`) | Component owns persistent or shared state. |
| `data/state/<name>/<name>.test.ts` | Always paired with a state store. |
| `data/mocks/<name>.json` (`@data/mocks`) | Mock data needed for stories or tests. |

## State store decision

The right pattern depends on what the state needs to do.

| Need | Pattern |
|---|---|
| Ephemeral, single component | React `useState` — no store needed |
| Shared across components, no persistence | `createSyncedStore` with `restore: "never"` |
| Persists during browser session | `createSyncedStore` with `restore: "session"` |
| User preference, survives browser close | `createSyncedStore` with `restore: "device"` |
| Coordinator-proxied API cache | Plain `create()` + `devtools()` — not `createSyncedStore` |

`syncKey` convention: `"app:<kebab-component-name>"`.

Store exports: `use<Name>` (component hook), `use<Name>Store` (debug/test access only).

## FTL scope

Everything a user can read, hear, or interact with goes in `component.ftl`. This includes:

- Visible labels and headings
- Button text
- Tooltips and title attributes
- Placeholders
- Error and empty state messages
- All `aria-label` and `aria-description` values (even if not visible on screen)

Nothing is hardcoded. If it reaches the user in any form, it has an FTL key.

Key naming: `<component-name>-<element>-<descriptor>`. Examples:

```
weather-button-hide = Hide weather
weather-aria-change-location = Change location
weather-label-temperature = { $temperature }°
weather-error-unavailable = Weather unavailable
```

## CSS conventions

- Root class is always `.base`
- Container queries over media queries
- CSS variables only — no raw values
- Available variables (from `ui/styles/css/`):
  - Spacing: `--space-{xxsmall,xsmall,small,medium,large,xlarge,xxlarge}`
  - Color: `--color-{gray,blue,...}-{0-110}`, `--color-white`
  - Semantic: `--background-color-{box,canvas,...}`, `--text-color{,-deemphasized,...}`
  - Border: `--border-{color,color-card,radius-small,radius-medium,radius-large,width}`
  - Typography: `--font-size-{xsmall,small,root,large,...}`, `--font-weight{,-bold,-semibold}`
  - Shadows: `--box-shadow-{card,card-hover,popup,tab}`
  - Icons: `--icon-{color,size,...}`
  - Components: `--button-*`, `--input-*`, `--link-*`
  - Z-index: `--z-index-{dropdown,sticky,overlay,modal,tooltip}` (10/20/30/40/50)
- New semantic tokens: add to `ui/styles/tokens/newtab-tokens.json`
- Needed but not yet tokenized: stub at top of the CSS module with a `/* TODO: token */` comment

## Import order

ESLint enforces and auto-fixes this. The order for reference:

1. Styles (`*.css`)
2. Testing (`@testing-library`, `vitest`)
3. External + workspace (`react`, `@ui/`, `@data/`, `@common/`, `@config/`)
4. Relative imports
5. Type-only imports (`import type`)

## Storybook

- Title format: `"ComponentName / StoryName"` — exactly two levels, no nesting beyond that
- One `Overview` story per component; add named stories only for meaningfully distinct states
- Use controls for variants — don't duplicate stories for minor prop differences
- Story file: `component.story.tsx` (not `.stories.tsx`)
